# Goal, Context Budget, And Resume

Use this reference when a long workflow uses Codex goals, may compact, or pauses for a human decision.

## Goal Binding

Use goal tools only when the user or governing environment authorizes goal-oriented work. Inspect active goal state before creating one. Reuse a relevant active goal; do not alter an unrelated goal. Create at most one goal for the stable objective and update it only for supported terminal states.

A unit blocker is not automatically a terminal goal blocker. Keep the goal active while meaningful progress or a human-decision resume remains possible.

## Context Budget

Checkpoint before context pressure degrades source fidelity or verification. Preserve:

- objective and hard boundaries
- controlling sources and material coverage
- decisions and explicit waivers
- completed, active, blocked, and remaining units
- changes and evidence
- worker terminal states
- current blocker and smallest question
- exact next action

Use one compact ledger or handoff artifact. Do not duplicate the full conversation.

## Human Decision Resume

Before asking:

1. Record the blocker and why it is material.
2. Name affected requirement and work-unit IDs.
3. Record the last completed step and next action.
4. Ask the smallest sufficient question.

After the answer:

1. Classify it as clarification, scope change, waiver, deferral, blocker resolution, disposition, cancellation, or authority change.
2. Update affected decisions and coverage.
3. Invalidate only downstream artifacts whose assumptions changed.
4. Resume from the recorded next action.

Do not restart profile selection or unrelated completed work unless the answer changes the objective or governing boundaries.
